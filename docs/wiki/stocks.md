# 주식 시세와 예측 규칙

검증일: 2026-10-01 · 기존 규칙: `b7b1b69`, [S4](sources.md#s4), [S5](sources.md#s5) · 갱신 오류 보완: `v1.22.1` / `7621465`, [S13](sources.md#s13).

## 현재가와 등락률을 분리해서 확인

미국 토스 시세는 실제 체결 시각을 공식 거래 달력의 구간과 비교합니다. 정규장 시작일이 거래일의 기준이며, 단순히 컴퓨터 날짜나 배열의 다음 일봉을 전일 종가로 사용하면 안 됩니다.

| 체결 세션 | 앱이 사용하는 등락률 기준 종가 |
| --- | --- |
| 주간·프리마켓·정규장 | 해당 거래일보다 앞선 가장 최근 정규장 종가 |
| 애프터마켓 | 해당 거래일의 완료된 정규장 종가 |

애프터마켓에는 정규장 종료 전에 요청한 일봉 캐시를 사용하지 않습니다. 세션이 모호하거나 체결 시각·기준 종가가 없으면 등락률은 비워 둡니다. 이미 시각이 있는 시세를 더 오래된 응답이나 시각 없는 응답으로 덮어쓰지 않으며 미래 체결도 거부합니다. 따라서 현재가가 같아도 기준 종가가 다르면 등락률이 달라집니다. 근거는 `StockQuoteCodec.accepts/usSession/changeBasis`와 Windows `quoteContext/canAcceptQuote`입니다. [S4](sources.md#s4)

## 차트와 조회

### 일시적인 조회 실패와 등락률 유지

1.22.1 소스에서는 종가·거래 달력 요청이 일시적으로 실패해도, 현재 체결에 유효한 기존 기준을 보존합니다. 이전 구현은 이 값을 지워 현재가는 움직이지만 등락률이 `—`로 사라지고 상승·하락 색상도 없어질 수 있었습니다. 공개 모의 응답으로 macOS의 실제 자동 갱신과 Windows Store에서 재현했습니다. 실제 사용자 환경의 HTTP 오류 코드는 수집하지 않았습니다.

- 미국은 공식 거래 구간에 포함되는 체결만 계산하며, 세션이 바뀌면 새 구간에 유효한 종가를 다시 확인합니다. 애프터마켓에는 정규장 종료 후 요청한 당일 종가만 허용합니다.
- 한국은 체결의 한국 날짜가 바뀌면 이전 날짜에 요청한 일봉을 재사용하지 않습니다.
- 처음부터 기준이 없거나 성공 응답에 필요한 종가·공식 거래 구간이 없으면 등락률을 비웁니다. 원래의 체결 시각과 과거·미래 응답 거부 규칙을 유지합니다.
- macOS 호버의 주식 변동 막대는 사용자 지정색보다 상승 녹색·하락 빨간색을 우선합니다. AI 사용량·시스템 항목의 색상 설정에는 영향을 주지 않습니다.

검사와 배포 여부는 [S13](sources.md#s13)에 구분합니다.

### 봉 차트

- 표시할 봉은 최대 20개입니다. 이동평균·분석에 필요한 과거 봉은 표시 범위보다 많이 읽을 수 있습니다.
- 차트 갱신 간격은 종목·봉 종류별로 1분봉 60초, 10분봉 600초, 일봉 86,400초입니다. 10분봉은 1분봉을 묶어 만듭니다. 시세와 등락률 기준 종가의 갱신은 이 차트 주기와 별개입니다.
- Finnhub 모드는 미국 시세용이며 토스 차트·분석이 지원된다고 표시하지 않습니다. [S2](sources.md#s2) · [S4](sources.md#s4)

## 예측이 실제로 하는 일

현재 GBM은 기대수익률을 0으로 둡니다. 예상 종가의 기댓값은 입력 현재가이고, 관측한 변동성과 정규장 마감까지 남은 시간으로 상승 확률과 가격 구간을 구합니다. 선택한 봉이 바뀌면 변동성 입력이 달라지며 목표는 같은 날 정규장 종가입니다. 이는 검증된 적중률이나 매매 수익률이 아닙니다. [S5](sources.md#s5)

관심 종목 예측은 보유 종목 없이 사용할 수 있고, 계좌 선택은 별도 동의입니다. 저장한 예측과 관측 추이는 구분하며 놓친 과거 예측을 사후 생성하지 않습니다. [S2](sources.md#s2) · [S4](sources.md#s4)

macOS의 수동 Codex 분석은 공개 체결가·정규장 시각·완료 일봉을 고정한 입력을 사용합니다. 현재 프롬프트는 뉴스·외부 시세·파일·계좌 자료를 사용하지 않도록 제한하며, 실제 모델명과 결과를 보관하고 같은 입력의 GBM과 비교합니다. 이 위키를 만들었다고 Codex 입력에 위키나 뉴스가 추가되는 것은 아닙니다. [S5](sources.md#s5)

## 수정 전에 점검할 것

1. 현재가, 체결 시각, 세션, 거래일, 기준 종가 날짜를 각각 비교합니다.
2. 과거·미래·시각 없는 응답, 휴장일, 정규장 종료 경계와 캐시를 회귀 검사합니다.
3. 모델을 비교할 때 같은 종목·시점·입력·평가 대상을 사용합니다. 이미 결과를 본 기간을 새 평가로 포장하지 않습니다.
4. 계좌번호·수량·잔고·인증 정보는 위키와 공개 이력에 넣지 않습니다.

프로젝트 범위는 [목표](project.md), 배포와 플랫폼 검증의 한계는 [검증 페이지](maintenance.md)에서 확인합니다.

## 명시적으로 여는 내 토스 계좌

### 1.24.1의 목적별 설정

주식 설정은 **관심 종목·내 계좌·분석·기록** 네 탭으로 나눕니다. 기본은 관심 종목이며 종목 추가·표시·순서 조작을 먼저 배치합니다. 연결과 표시 옵션은 접고, 차트·기술적 분석·예측은 분석에서, 저장 결과·비교·내보내기는 기록에서 확인합니다. [S16](sources.md#s16)

- 계좌 불러오기와 선택은 내 계좌 한곳에 모읍니다. 노치 표시와 보유 종목의 예측 포함은 별도 선택이며 예측 기능 자체를 자동으로 켜지 않습니다.
- 탭을 열거나 계좌 목록을 읽는 것만으로 저장된 계좌 선택을 바꾸지 않습니다. 기존 노치/예측의 서로 다른 선택값도 보존합니다. 사용자가 다른 계좌를 직접 선택하면 이미 켜져 있는 계좌 기능이 그 선택을 따릅니다. 예측 포함은 계좌를 다시 읽지 않고도 끌 수 있습니다.
- 기본 계좌 요약은 평가금액·일간 손익·일간 수익률입니다. 투자원금·누적 손익·세금과 수수료·보유 종목은 펼쳐볼 수 있습니다. 계좌 노치가 꺼져 있으면 내 계좌 탭을 떠날 때 개인 뷰어를 지웁니다. 켜진 계좌 노치는 계속 동작합니다.
- Windows는 입력칸 자동 포커스로 상단 설정이 가려지지 않도록 탭에 포커스를 둡니다. 키 입력을 떠날 때 비밀 입력을 지우고, 공개 시세 갱신에서도 선택 탭·입력 포커스·펼친 상세 상태를 보존합니다. 분석과 기록의 오류는 해당 화면에서 확인합니다.
- UI 구성을 바꾸며 기존 계산·기록 형식·키 저장소·조회 주기는 유지합니다. Windows에 구현되지 않은 Codex 분석 버튼은 추가하지 않습니다.

아래 1.23.0과 1.24.0 설명은 최초 구현 기록입니다. 화면 구성과 계좌 선택 조작은 이 1.24.1 규칙으로 보완합니다. 실제 계좌 금액 대조와 Windows 실기 여부는 [S16](sources.md#s16)에 별도로 기록합니다.

1.23.0 작업 소스의 **설정 → 주식 → 내 토스 계좌**는 기존 예측 계좌 선택과 별개의 메모리 전용 화면입니다. macOS와 Windows 모두 계좌 불러오기 → 직접 선택 → 새로고침/숨김 순서로 사용합니다. 노치 주식 표시와 예측이 꺼져 있어도 토스 제공처와 저장한 인증 정보가 있으면 조회합니다. 화면 열기만으로 계좌를 자동 조회하거나 단일 계좌를 자동 선택하지 않습니다. [S14](sources.md#s14)

- `/api/v1/accounts`의 계좌번호는 가리고, 선택한 `accountSeq`로 고정 GET `/api/v1/holdings`를 호출합니다. 주문·송금 API는 추가하지 않았습니다.
- 원화·달러의 투자원금, 평가금액, 손익, 일간 손익과 종목별 수량·평균 매입가·현재가·비용을 표시합니다. 수량은 소수점, 금액은 최대 30자 decimal 문자열을 처리합니다. `0.1077`은 10.77%이며 전체 손익률은 공식 명세의 원화 환산 기준입니다. 통화를 더하거나 현금 잔고를 계산하지 않습니다.
- 새 시장·통화 enum은 제한된 문자열로 표시하고, 알려진 시장·통화 불일치·잘못된 금액·중복 종목·오류 응답은 스냅샷으로 사용하지 않습니다. 허용된 null은 `—`이며 0으로 바꾸지 않습니다.
- 1.23.0의 뷰어 전용 수명은 아래 1.24.0 계좌 노치 규칙으로 보완됩니다. 계좌 노치가 꺼져 있을 때 설정 종료/탭 이동은 뷰어 금액을 지웁니다. 명시적 숨김·제공처·인증 정보 변경은 이전 금액과 늦은 응답을 폐기합니다. Windows의 개인 응답은 JS·네이티브 캐시를 우회합니다. 계좌 데이터는 공개 이력·CSV·AI 입력에 들어가지 않습니다.

현금·채권·옵션은 이 화면의 범위 밖입니다. 실제 사용자 계좌 조회·금액 대조와 실제 Windows Credential Manager 실행은 검증하지 않았으며, 정식 배포 여부와 검사 근거는 [S14](sources.md#s14)에 구분합니다.

## 계좌 노치의 일간 증감

1.24.0 작업 소스 기준입니다. [S15](sources.md#s15) · 확인일 2026-10-01.

- **노치에 계좌 표시**는 기본 꺼짐입니다. 명시적으로 조회·선택한 계좌만 켤 수 있고 예측용 계좌 선택과 별도입니다. 저장된 선택값은 계좌번호가 아닌 불투명한 식별자입니다.
- 노치 `widget-account`는 API의 `dailyProfitLoss.rate`를 보여줍니다. 이는 원화 환산 비율이며 조회 후 잔고 차이, 누적 투자 수익률 또는 예측값이 아닙니다. 녹색 시계 방향/빨간색 반시계 방향 원호와 일반 막대 형식을 사용합니다.
- 호버에는 통화별 `marketValue.amount`와 `dailyProfitLoss.amount`, 조회 시각을 표시합니다. 서로 다른 통화를 더하지 않으며 현금·채권·옵션을 포함한 총액을 만들지 않습니다. 원호 크기는 종목 원호와 같은 30% 척도이고 숫자에는 실제 일간 증감률이 표시됩니다.
- 활성화된 노치만 60초마다 개인 데이터를 조회하며 요청을 겹치지 않습니다. 실패하면 금액을 비우고 `—`/오류를 표시합니다. 설정 창을 닫아도 이미 켠 노치의 수명은 유지됩니다. 끄면 조회와 메모리 금액을 지웁니다. 다른 제공처·인증 정보·선택 계좌로 바뀐 이전 응답은 폐기합니다.
- macOS 설정과 노치는 한 메모리 스냅샷과 기존 공유 인증 토큰을 재사용합니다. Windows에서는 노치 owner만 자동 갱신하고 설정 뷰어는 수동 조회합니다. 새 토큰 캐시나 영구 잔고 저장소를 만들지 않습니다.
- 최적화는 데이터가 바뀌지 않은 개인 뷰어 갱신과 불필요한 계좌 읽기를 줄이는 범위입니다. CPU 사용률이나 실행 속도의 개선 비율은 측정 없이 주장하지 않습니다.

실계좌 금액 대조, 실제 Windows 기기·자격 증명 검증 및 정식 배포는 자동 테스트와 구분합니다. 검증 결과는 [S15](sources.md#s15)에 누적합니다.
