# 노치와 릴리즈 검증

검증일: 2026-09-29 · 현재 배포: `v1.22.1`의 `7621465`, [S13](sources.md#s13). 아래 이전 버전 기록은 당시 근거를 보존합니다.

## 노치 스크롤의 유지 조건

화면보다 긴 목록만 휠·트랙패드로 이동합니다. 네 방향과 원형·막대를 지원하며, 상하 노치에서도 세로 휠을 사용할 수 있습니다. 목록이 들어맞으면 스크롤하지 않습니다. 노치 본체·손잡이는 화면 안에 유지하고 호버 카드의 스크롤은 따로 처리합니다. [S3](sources.md#s3)

렌더링과 호버·클릭·드래그의 좌표가 같은 스크롤 위치를 사용해야 합니다. 보이지 않는 항목은 입력 대상에서 제외하고, 항목 수가 줄면 이동 범위를 다시 제한합니다. 짧은 클릭과 Option/Alt로 노치를 옮기는 동작도 보존합니다. macOS `NotchScrollTests`와 Windows 브라우저 검사는 이 조건을 확인하는 출발점입니다. [S3](sources.md#s3)

## 원본 업데이트 통합

2026-09-29 KST에 CodeNotch 1.19.0을 PenguinNotch 1.21.0(macOS build 58, Windows r50) 소스에 반영했습니다. 기존 스크롤은 카메라 옆 배치에서도 같은 렌더링·입력 좌표를 사용합니다. 긴 목록의 보이는 길이와 손잡이는 화면에 맞추고, 투명한 애니메이션 여유 공간 때문에 카메라 기준점이 이동하지 않도록 처리합니다. 주식의 단일 항목은 가격·등락률 교대와 방향 색상을 유지합니다. [S9](sources.md#s9)

macOS의 새 업데이트 카드는 사용자가 **업데이트** 또는 **나중에**를 선택합니다. 주식 저장·모델 계산 방식은 유지하며 연구 스크립트·평가 결과를 앱에 채택하지 않습니다. 검증 범위는 S9에 기록합니다. 이 병합 자체는 정식 설치 파일 배포·설치가 아닙니다.

최종 로컬 검증은 macOS 전체 2,186개 중 실패 0·건너뜀 11개, Windows Rust 184개 통과·4개 제외, Windows GNU 교차 컴파일, Node 19개 및 브라우저 설정 24개·노치 48개 배치 검사입니다. 노치를 옮기거나 늘릴 때도 스크롤 위치와 표시 형식, 화면에 보이는 항목만 유지합니다. Apify의 명시적인 키체인 접근 허용, Codex 완료 알림, JSON 합계 범위 검사도 포함합니다. 실제 Windows 창 동작과 실제 계정은 별도 검증 대상입니다. [S9](sources.md#s9)

## 빠른 드래그의 놓기 처리

검증일: 2026-09-29 KST · 기준: `34d30cb` 이후 1.21.1 소스(macOS build 59, Windows r51). 중간 `mouseDragged`가 없이 `mouseUp`만 전달되는 합성 입력에서 기존 구현은 이동한 거리에 관계없이 클릭했습니다. 이제 놓은 위치가 시작점에서 5포인트 이상 떨어지면 재정렬을 완료하고, 그보다 짧으면 클릭을 유지합니다. Option 이동과 이미 시작된 드래그의 판정은 유지합니다. [S10](sources.md#s10)

이 입력 경로의 회귀는 수정 전 실패·수정 후 통과로 확인했습니다. 원본 통합 커밋은 로컬 전체 검사에는 성공했지만 GitHub macOS CI 두 번 모두 작은 목록 재정렬 검사에서 실패했습니다. 중간 이벤트 누락이 그 CI 실패의 원인인지는 확인되지 않았으며, 드롭 호출·좌표·클릭·호버 진단으로 구분합니다. Windows 네이티브 테스트와 설치·doctor·제거 검사는 해당 통합 커밋에서 성공했습니다. [S10](sources.md#s10)

## 합성 이벤트의 좌표 문제

검증일: 2026-09-29 KST · 기준: `2ae6eb1` 이후 1.21.2 소스(macOS build 60, Windows r52). 1.21.1 GitHub 검사에서는 드롭 콜백이 실행됐지만, 기대 좌표 `(100, 100)`이 `(100, -468)`로 바뀌었습니다. 실제 재정렬 대상 좌표도 달라져 입력 대상 밖으로 나갔습니다. 따라서 이 검사 실패를 단순한 드래그 이벤트 누락으로 볼 수 없습니다. 로컬 macOS 27과 CI macOS 26의 합성 이벤트 큐에서 서로 다른 결과가 관측됐습니다. [S11](sources.md#s11)

1.21.2의 테스트는 유한한 이벤트 목록을 패널에 공급하고, 실제 `mouseDown`·히트 테스트·재정렬·숨김 항목 보존·클릭 동작과 기존 단언을 그대로 실행합니다. 실제 앱은 공급자를 설정하지 않아 이전과 동일한 AppKit `nextEvent`를 사용합니다. 운영체제별 임의 좌표 보정이나 검사 생략은 넣지 않습니다. [S11](sources.md#s11)

최종 코드 `3fe7ab5`의 macOS 26 CI는 2,187개 중 건너뜀 13개·실패 0으로 통과했습니다. Windows CI도 188개 통과·4개 제외이며, 설치·doctor·제거·업데이트 피드 생성까지 성공했습니다. 이전 로컬/CI 결과 차이와 실패 기록은 원인 추적을 위해 보존합니다. [S11](sources.md#s11)

## 1.22.0 Windows 일관성 검증

검증일: 2026-09-29 KST · 소스 버전 1.22.0(macOS build 61, Windows r53). Windows 사용량 표시·한도 설정, 여섯 점 이동 손잡이, 업데이트·나중에·미리보기, 날씨 상세를 macOS 동작에 맞췄습니다. 기존 설정을 보존하고 저장 실패 시 새 값을 확정하지 않습니다. 주간 대표 표시와 사용 속도는 실제 한도 기간이 있을 때만 계산합니다. 도시 변경 중 늦게 도착한 날씨와 현지 날짜가 지난 예보도 구분합니다. [S12](sources.md#s12)

로컬 macOS 전체 검사 2,187개 중 건너뜀 11개·실패 0, Mac 호스트의 Windows Rust 검사 224개 통과·4개 제외, Windows GNU 전체 대상 교차 컴파일, Node 33개 및 UI 3개 문법 검사가 통과했습니다. 실제 HTML을 Chromium에서 실행하여 설정 24개 배치, 노치 48개 배치와 추가 주간 수치 48개 조합, 네 방향·원/막대의 업데이트 카드 및 연속 클릭을 확인했습니다. 네이티브 IPC는 공개 모의 자료를 사용했습니다.

위 결과는 로컬 검증이며 원격 검증과 구분합니다. 후속 macOS CI는 2,187개 중 건너뜀 13개·실패 0, Windows 네이티브 CI는 228개 통과·4개 제외입니다. Windows 설치·doctor·제거 검사와 두 업데이트 서명 검증 후 1.22.0을 정식 게시했습니다. 배포 증거는 S12에 누적합니다. 전체 기능이 동일하다는 뜻은 아니며 [남은 플랫폼 차이](project.md#1220-공통-조작과-남은-차이)를 유지합니다.

## 1.22.1 주식 갱신과 색상 검증

정식 소스 `7621465`에서 macOS CI 2,194개 중 건너뜀 13개·실패 0, Windows CI 228개 통과·4개 제외를 확인했습니다. 일시적인 통신 실패와 잘못된 달력 응답을 구분하고, 거래 구간이 바뀔 때 이전 기준이 적용되지 않도록 검사했습니다. macOS 모의 요청의 검사 간 간섭은 세션 식별자로 차단했습니다. 이전 로컬 애니메이션 실패·첫 CI 실패·Windows PowerShell 시간 초과와 재시도도 [S13](sources.md#s13)에 남깁니다.

이 Mac에는 기존 Apple Development 인증서를 유지한 1.22.1/build 62를 설치하고 프로세스와 새 기능 안내를 확인했습니다. 공개 DMG의 임시 서명과 이 Mac의 개발 인증서 서명은 별개이며, 실제 Toss 계정의 장시간 수신이나 물리적 Windows 기기 동작을 확인했다는 뜻은 아닙니다.

## 확인된 문서 불일치

**미해결 — 기여 문서의 키체인 설명:** S7의 `CONTRIBUTING.md`는 백그라운드 키체인 읽기가 거부되면 `/usr/bin/security`로 재시도한다고 설명합니다. 같은 커밋의 Claude·Antigravity 코드는 이 재시도를 제거하고 명시적인 접근 허용 동작을 기다립니다. 1.20.1 릴리즈 노트도 제거 사실을 기록합니다. 현재 인증 동작을 수정할 때는 이 오래된 문장을 구현 지침으로 사용하지 말고 해당 코드를 확인해야 합니다. [S7](sources.md#s7)
