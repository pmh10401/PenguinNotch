# 정규장 종가 예측 통합과 과거 평가 설계

작성일: 2026-10-02 · 코드 기준: `92ddece9aa88d7c2206753e13ee9fe1239603bab` · 현재 앱: 1.24.1

상태: 사용자가 목표와 범위를 승인한 뒤 작성한 **검토용 설계**. 앱 구현·과거 데이터 수집·새 모델 실행은 아직 수행하지 않았다. 이 문서 승인 후 구현 계획을 작성한다.

## 목적과 성공 조건

사용자는 주가 예측 기능을 통합하고 과거 자료로 각 모델의 성능을 검수하려 한다. 첫 목표는 **같은 거래일의 정규장 종가**다. 예측 수치를 많이 보여주는 것보다, 어떤 입력으로 언제 예측했고 현재가 유지 기준선보다 무엇이 나은지 확인할 수 있어야 한다.

성공 조건은 하나의 기록 화면, 봉별 재현 가능한 평가, 동일 입력의 대응 비교, 기존 데이터 보존이다. macOS와 Windows는 같은 기본값·계산·평가 용어를 사용한다. 실제 Codex 분석 실행은 현재 macOS 전용이라는 제한을 유지한다.

## 승인 범위와 기본값

| 항목 | 이번 구현의 계약 |
| --- | --- |
| 예측 목표 | 해당 거래일의 완료 정규장 종가 |
| 과거 평가 시점 | 공식 정규장 종료 60분 전 |
| 기본 평가 기간 | 최근 완료 거래일 60개; 사용자가 20/60/120개 중 선택 |
| 종목 | 사용자가 선택한 관심 종목, 최대 30개; 실행 시작 때 목록 고정 |
| 데이터 제공자 | 토스 OpenAPI; Finnhub 시세 모드에서는 지원하지 않는 이유 표시 |
| 과거 평가 모델 | 기존 계산식의 GBM 1분봉·10분봉·일봉 변형과 현재가 유지 기준선 |
| 실제 저장 응답 | 기존 GBM·Codex 이력; 수동/자동을 분리 |
| 새 LLM 호출 | 없음; 기존 Codex 수동 분석 동작 유지 |
| 노치 차트 | 표시 봉 최대 20개와 현재 조작 유지 |

60거래일은 초기 실행량을 제한하기 위한 기본값이며 유효한 검증 표본 수를 보장하지 않는다. 과거 분봉 제공 기간과 완전성을 실제 조회로 확인하고 부족하면 실패·누락을 표시한다. 요청한 기간을 조용히 줄이거나 가장 좋은 결과만 채택하지 않는다.

## 선택한 구조

**기존 저장소를 함께 읽고, 과거 재현은 별도 실행 폴더에 저장한다.** 기존 JSON과 Windows SQLite를 새 통합 DB로 옮기는 안은 데이터 이동과 회귀 위험이 커서 선택하지 않았다. 과거 재현을 기존 실시간 저널에 넣는 안은 당시 예측과 사후 계산을 혼동시키므로 선택하지 않았다.

공통 흐름은 다음과 같다.

1. 기록 화면은 기존 저장 기록을 읽기 전용으로 정규화한다.
2. 과거 평가를 명시적으로 시작하면 종목·기간·모델 버전·입력 규칙을 고정한다.
3. 기존 토스 인증·전송 경로로 공식 달력과 캔들을 모은다. 계좌 API는 호출하지 않는다.
4. 각 종목/거래일의 입력을 동결하고, 목표 종가를 가린 순수 계산 함수에 전달한다.
5. 예측 결과를 저장한 뒤 목표 종가와 결합하여 점수를 계산한다.
6. 같은 입력의 기준선 및 선택 모델과 비교한다. 완료 여부와 누락을 함께 표시한다.

범용 모델 플러그인, 별도 Python 런타임, 새 데이터베이스, 뉴스 수집 서비스는 만들지 않는다. 현재 GBM 계산·점수·토스 전송·파일 보존 패턴을 재사용한다.

## 기록 화면 통합

주식 설정의 기록 탭은 `예측 기록과 평가` 한 진입점으로 바꾼다. 내부에는 `실제 저장 기록`과 `과거 재현`을 구분한다. 요약에는 평가 건수, 기준선 대비 종가 오차, 확률 오차만 먼저 보이고 입력·응답·확률 구간·세부 표는 펼쳐서 본다.

- 실제 기록의 필터는 종목, 기간, 수동/자동, 모델이다. 모델 선택은 기록 목록을 좁히며 비교 집합은 명시적으로 선택한다.
- GBM과 Codex 원본을 옮기거나 다시 쓰지 않는다. Codex는 저장한 실제 모델명·프롬프트 버전·입력·응답을 사용한다.
- Codex의 대응 GBM은 기존 `pairedGBMRecord`처럼 동일 고정 입력에서 계산한다. 이 결과는 `대응 기준 계산`으로 표시하고 당시 별도로 실행한 응답처럼 표시하지 않는다.
- 근거가 없는 오래된 기록은 자체 오차와 가격 유지 기준선까지 볼 수 있다. 다른 모델과 동일 입력임을 증명할 수 없으면 대응 비교에서 제외한다.
- Codex의 보류 응답은 보류 건수에 포함한다. 예측한 건수만 분모로 삼은 오차와 전체 요청 중 예측 비율을 함께 표시한다.
- 기존 기록·CSV 진입점은 같은 통합 화면으로 연결한다. 필터, 원본 근거, CSV 수식 주입 방지와 열린 상세 항목 보존을 유지한다.
- Windows에는 동작하지 않는 Codex 실행 버튼을 추가하지 않는다. 저장된 지원 기록과 과거 GBM 평가는 같은 구성으로 제공하며 macOS 전용 실행 제한을 안내한다.

## 과거 데이터와 시간 규칙

### 거래일과 예측 시점

공식 달력의 거래일별 정규 구간 `[start, end)`를 사용하고 `cutoff = end - 60분`으로 고정한다. 미국은 뉴욕 거래일·DST·조기 종료를 반영한다. 한국은 현재 앱이 사용하는 토스 통합 `integrated.regularMarket` 기준이며, 이를 KRX 단독 종가 평가라고 표기하지 않는다. 공급자가 다른 세션의 일봉을 반환해 목표와 일치함을 확인할 수 없으면 그 사례를 제외한다.

휴장일, 길이가 60분 이하인 구간, 모호한 달력, 목표 일봉 부재는 이유를 기록한다. 컴퓨터의 오늘 날짜나 봉 배열의 다음 항목으로 전일 종가를 추정하지 않는다.

입력 현재가는 cutoff까지 완료된 마지막 1분봉 종가로 재구성한다. 마지막 봉 종료가 cutoff보다 늦거나 120초 넘게 오래되면 공통 사례를 제외한다. 이것은 실제 당시 체결 응답이 아닌 **분봉 종가 대용값**이며 실제 저장 기록의 quoteAt과 섞지 않는다.

재현 모델의 남은 시간은 `end - cutoff`로 계산한다. 원자료 마지막 봉의 종료 시각과 실제 수집 시각은 별도로 보존하며, 이를 실시간 quoteAt으로 꾸미거나 수집 시각을 예측 시점으로 쓰지 않는다.

### 가격 기준과 정보 누출

기존 실제 기록의 입력 수정 일봉과 당시 관측 단위의 비수정 실제 종가 연결 규칙은 바꾸지 않는다. 기존 정산 요청 `adjusted:false`도 유지한다.

새 과거 재현은 **조회 당시 공급자 수정 가격 기준**으로 통일한다. 입력 분봉, 과거 일봉, 전일 종가, 목표 일봉 모두 명시적으로 `adjusted:true`를 요청한다. 당시 비수정 시세를 끼워 넣거나 목표 종가를 이용해 입력 가격을 보정하지 않는다. 같은 시각의 중복 봉 가격이 충돌하면 해당 사례는 확정하지 않는다.

이 자료는 당시 이용 가능했던 가격 수정 버전을 보장하지 않는다. 화면·CSV·보고서에 `현재 조회 자료로 재구성; 당시 정보만 사용한 검증을 보장하지 않음`을 표시한다. 공급자의 수정 계수와 기업행동 이력이 없으면 분할·배당 영향을 완전히 제거했다고 주장하지 않는다. 가격 단위나 세션 일치를 검증하지 못한 사례는 점수에 넣지 않는다.

### 봉별 입력

세 모델은 동일 종목·거래일·cutoff·현재가·전일 종가·목표와 동결된 원자료를 공유한다. 선택 봉은 변동성 근거만 바꾼다.

| 모델 식별자 | 입력 규칙 |
| --- | --- |
| `GBM daily zero drift v1 / replay v1` | 해당 거래일 이전 완료 일봉 61개, 로그 수익률 60개 |
| `GBM 1m zero drift v1 / replay v1` | 현재 정규장 시작부터 cutoff까지 완료 1분봉; 마지막 연속 구간의 수익률 최소 10개 |
| `GBM 10m zero drift v1 / replay v1` | 같은 1분 원자료를 기존 정규장 완료 봉 규칙으로 10분 집계; 마지막 연속 구간의 수익률 최소 10개 |

10분 집계의 기준 시각·완료 판정·거래량 합산은 기존 `completedRegularBars`와 Windows 집계 규칙에 맞추고 공통 공개 fixture로 확인한다. 장외 봉, 미완성 봉, 다음 거래일 봉은 입력에서 제외한다. 누락 구간을 채워 넣거나 밤사이 수익률을 분봉 변동성에 넣지 않는다.

일봉 61개가 부족하면 일봉 모델만 `insufficient_daily_history`다. 분봉이 부족하면 해당 모델만 보류하며, 사용 가능한 모델의 자체 점수는 유지한다. 전체 모델 비교에는 모두 성공한 공통 사례만 사용한다.

기존 식처럼 기대 종가는 현재가와 같다. 세 GBM의 종가 점 오차가 가격 유지 기준선과 같다는 사실을 화면에 명시한다. 봉별 검수의 실질적인 비교 대상은 확률과 가격 구간이다. 기존 `GBM zero drift v1` 기록을 새 봉별 모델명으로 재분류하지 않는다.

## 데이터 계약과 보존

### 실제 기록의 공통 읽기 형식

원본 저장 형식을 유지하고 메모리에서 `source`, 원본 참조, 모델/프롬프트 버전, capture, 거래 시각, 입력 가격과 근거, 출력, 실제 종가/정산 시각을 갖는 읽기 항목으로 변환한다. 실제 저장, 대응 계산, 과거 재현은 서로 다른 source다. 이름이나 행 번호로 기록을 연결하지 않는다.

같은 입력의 판정은 종목·통화·capture·거래 구간·quoteAt·입력/전일 가격·전체 동결 근거가 같아야 한다. 출력과 완료 시각은 비교 키에서 제외하지만 원본에 보존한다. 분봉 변형은 모델별 관측 개수가 다르므로 공통 원자료 참조로 대응시키고 관측 수 일치를 강요하지 않는다.

### 별도 과거 실행 아카이브 v1

macOS는 앱 지원 폴더의 `Forecasts/Backtests/<runUUID>/`, Windows는 앱 설정 경로 부모의 같은 하위 폴더를 사용한다. 기존 `history.json`, `AIAnalyses/history.json`, `CloseEstimates`, `stock-history.sqlite3`에 재현 행을 쓰지 않는다.

| 파일 | 필수 내용 |
| --- | --- |
| `manifest.json` | version=1, runUUID, 생성/수집 시각, 코드·입력 규칙·모델 버전, 고정 종목/거래일, cutoff 규칙, 가격 기준, 원자료 파일 SHA-256, 사례별 상태·누락 이유, 실행 완료 상태 |
| `cases/<caseID>.json` | version=1, 종목/시장/통화, 거래일·세션·cutoff, 입력 현재가와 그 봉 종료 시각, 전일 종가, 과거 완료 일봉, cutoff 이전 분봉, 별도 목표 종가와 출처/조회 시각 |
| `results/<caseID>.json` | version=1, caseID와 입력 파일 해시, 계산 버전, 모델별 성공/보류 및 이유, 예상 종가·상승 확률·80% 구간·관측 수, 계산 시각 |

caseID는 실행 안의 고정 종목/거래일 참조다. 모델 출력은 목표를 제거한 입력 객체만 받는다. 결과 파일을 저장한 뒤 평가 함수가 목표와 결합한다. 입력 해시가 바뀌면 기존 결과를 재사용하지 않는다.

시간은 안전한 정수 epoch milliseconds, 가격·OHLC는 양의 유한 수, 거래량은 유한 비음수다. 날짜는 시장 현지 YYYY-MM-DD다. 알려지지 않은 필드, 계좌·보유 수량·잔고·인증 필드는 모든 중첩 단계에서 거부한다. 기존 Swift Decimal과 JS 수 표현의 차이는 공통 fixture의 허용 오차로 검증하며 원본 JSON 가격을 재저장해 정밀도를 바꾸지 않는다.

사례당 일봉 최대 61개, 원자료 분봉 최대 1,400개다. 입력·결과 파일을 분리해 실행마다 거대한 이력 전체를 다시 직렬화하지 않는다. 작은 파일을 같은 폴더에 임시 작성한 뒤 원자적으로 교체하며 완료 입력/결과는 덮어쓰지 않는다. SHA-256은 파일의 실제 바이트를 대상으로 한다.

실행 재개는 UUID·프로토콜·파일 해시가 동일할 때만 누락 사례를 처리한다. 완료 사례는 변경하지 않는다. 손상 파일·알 수 없는 버전·해시 불일치는 해당 실행의 재개/쓰기를 막고 원본을 보존한다. 자동 삭제와 보존 기간 제한은 없다.

## 비교와 점수

기본 비교는 **각 모델 대 같은 사례의 현재가 유지 기준선**이다. 별도 `선택 모델 공통 비교`는 사용자가 선택한 모델만 교집합으로 묶는다. 관계없는 새 모델이나 미정산 기록이 기존 두 모델의 대응 집합을 지우지 않아야 한다. 실제 저장의 수동/자동과 과거 재현을 합쳐 순위를 매기지 않는다.

- 종가: MAPE와 동일 사례 기준선 MAPE, 둘의 차이(%p). 원시 MAE는 통화별로만 표시한다.
- 확률: 사건 `실제 정규장 종가 > 전일 종가`의 Brier. 보합은 사건 0으로 포함한다. 가격 유지 기준선에는 확률 점수를 임의로 부여하지 않는다.
- 방향 적중: 실제 보합과 확률 0.5는 제외하며 유효 분모·제외 건수를 표시한다. 기존 점수와 의미를 유지한다.
- 구간: 중앙 80% 구간 포함률과 평균 구간 폭/입력 가격(%). 넓은 구간으로 포함률만 높이는 결과를 개선이라고 표시하지 않는다.
- 확률 신뢰도: 기존 10%p 구간 표와 Wilson 95%를 재사용한다. 같은 거래일·종목의 상관을 고려하지 않은 설명용 집계임을 명시한다.
- 표본: 요청 사례, 확보 사례, 모델별 성공/보류, 정산, 대응 사례, 종목/거래일 수를 항상 표시한다. 누락과 보류를 오차 0으로 계산하지 않는다.

과거 평가 요약은 전체 외에 시장·종목·거래일별로 볼 수 있다. 모든 비교는 같은 목표 가격과 가격 기준을 요구한다. 예측 시점 이후 수익률이나 실제 매매 성과와 같다고 설명하지 않는다. 표본 부족 시 우승 모델 표시·자동 모델 전환을 하지 않는다.

현재 구현식의 고정 성능 검수에는 학습·파라미터 선택이 없다. 이후 모델/프롬프트를 개선한다면 실행 시작 때 앞 2/3 거래일을 개발, 뒤 1/3을 고정 검증으로 나누고 같은 날의 종목을 같은 구간에 둔다. 각 예측은 그 시점 이전 관측만 사용한다. 경계와 버전을 manifest에 보존하고 검증 결과를 본 뒤 다시 튜닝한 결과는 새 개발 실험으로 분리한다. 시간 순서 검증은 [FPP3](https://otexts.com/fpp3/tscv.html)를 따른다.

현재 LLM으로 옛 날짜를 다시 예측하는 기능은 이번 범위에서 제외한다. 후속 추가 시에는 `사후 LLM 재실행`으로 따로 평가한다. 학습 정보가 과거 시점을 넘어설 수 있다는 위험은 [Look-Ahead-Bench](https://arxiv.org/abs/2601.13770)의 방법론과 구분하여 명시하며, 특정 현재 모델의 누출을 입증했다고 주장하지 않는다.

## 조회, 실행 중단과 오류

[토스 공식 명세](https://openapi.tossinvest.com/openapi-docs/latest/openapi.json)에서 확인한 interval은 1m/1d, 페이지 최대 200봉이다. 10분봉은 직접 API 종류로 요청하지 않는다. before의 포함 경계와 정확한 nextBefore를 지키고 중복 시각을 제거한다. 고정 날짜 조회에 현재 일봉 캐시를 잘못 재사용하지 않는다.

기존 전송·토큰·401 갱신·429 제한 재시도를 재사용한다. 과거 수집은 한 요청씩 진행하고 페이지/사례 사이 최소 250ms를 둔다. 최초 분봉 조회는 before=cutoff로 제한하고 사례당 최대 8페이지/1,400봉, 일봉은 최대 200봉 한 페이지에서 과거 61개와 목표를 구분한다. 제공 범위 부족, 반복 cursor, 충돌 중복, 경계 불일치는 구체적인 누락 이유다.

동시에 한 과거 실행만 진행한다. 시작·취소·사용자 재개와 사례 완료 수를 표시한다. 이미 성공한 공개 입력은 고정 파일로 재사용하며 설정 화면 반복 렌더링으로 조회하지 않는다. 기존 전송 잠금은 요청 단위로만 사용하고, 페이지 간 대기나 파일 저장 중에는 잡지 않는다. 실시간 시세 갱신을 막는 장시간 잠금은 사용하지 않는다.

제공자·인증 상태가 바뀌면 새 요청과 대기 요청을 기존 generation 규칙으로 취소한다. 앱 종료나 잠자기 뒤 자동으로 대량 수집을 재시작하지 않는다. 사용자 재개 시 완료 자료는 유지하고 누락 사례만 처리한다. 인증 오류가 나면 실행을 일시 중단하며 계좌 호출이나 반복 키체인 프롬프트로 우회하지 않는다.

Windows는 설정을 실행 제어자로 두고 네이티브에 엄격한 전용 공개 입력/아카이브 IPC를 둔다. 임의 URL·임의 파일 경로를 받는 명령을 추가하지 않는다. 기존 실시간 저널의 노치 단독 writer 계약은 그대로 유지한다.

## 검증과 완료 기준

1. **데이터 보존:** 기존 v1 GBM·Codex·Windows history fixture의 원본 바이트 불변, 통합 읽기/CSV 유지, 손상·미지원 버전·저장 실패 시 원본 보존.
2. **시간/입력:** 미국 DST·조기 종료·주말, 한국 통합 세션, cutoff 경계, 일봉 날짜 누락, 미래/미완료 봉, 수정 기준 혼합, 중복 cursor와 봉 가격 충돌. 목표·cutoff 이후 가격을 바꿔도 예측 출력은 바뀌지 않아야 한다.
3. **계산/비교:** 같은 공개 fixture에서 Mac/Windows 가격 오차 1e-8 상대 오차 이내, 확률/집계 1e-6 절대 오차 이내; 보합·0.5·보류·누락·다른 통화·새 모델 추가·선택 교집합·모델별 관측 수 차이. GBM 기대값=입력 가격, MAPE=기준선은 정확히 확인한다.
4. **실행/UX:** 취소·제공자 변경·재개·중복 실행·부분 실패, 요청 상한·토큰 재사용·실시간 갱신 유지. Windows 렌더링에서 한/영, 필터·상세·CSV·진행 표시를 검사한다. Codex 새 호출/계좌 API 0건은 모의 전송으로 확인한다.
5. **자료 검수:** 실제 과거 시세 조회를 수행한 경우 요청/확보/누락과 출처 시각·해시·모델 버전을 로컬 보고서에 남긴다. 누락이 있으면 `완료(누락 있음)`과 모델별 유효 표본을 구분한다. 전체 요청을 검수하기 전 순위를 확정하지 않는다.

Swift 관련 테스트, Windows Node/네이티브 검사와 CI를 변경 위험에 맞춰 수행한다. 사용자 계좌·비밀키를 테스트 데이터로 사용하지 않는다. 자동/모의 검사와 실제 Windows 기기·공급자 과거 자료 검증은 다른 근거로 보고한다. 구현이 완료되면 두 플랫폼 버전을 올리되, 이 설계 작성은 앱 버전·설치본·릴리즈를 변경하지 않는다.

## 이번 범위에서 하지 않는 일

새 예측 모델 채택, GBM 기대수익률 튜닝, Grok/AGY 자동 예측 호출, 뉴스·계좌를 예측 입력에 추가, 매수/매도 자동 실행, 수익률 백테스트, 기존 기록 소급 생성·수정·삭제, OS 보안 경고 해결은 제외한다. 공개 문서에는 계약과 익명화한 검사 근거만 넣고 개인 이력·집계·원자료·인증·미추적 연구 파일은 올리지 않는다.

근거와 현재 한계는 [위키 S18](../../wiki/sources.md#s18), [주식 규칙](../../wiki/stocks.md#2026-10-02-예측-성과를-통합하기-전의-확인)에 보존한다.
